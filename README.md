# DeepAgent Demo

A collection of demo agents built with the [`deepagents`](https://github.com/langchain-ai/deepagents)
library and OpenAI models, using OpenAI's built-in provider-hosted **web search** tool —
no extra search API key or package required.

The repo contains three runnable scripts, from minimal to full-featured:

| Script | Purpose |
| ------ | ------- |
| `main.py` | Minimal smoke test — creates an agent and sends it `"Hi"` |
| `main2.py` | General-purpose research agent with live streaming, token statistics, and file export |
| `main-salesdig.py` | "Mini SalesDig" — B2B sales-intelligence agent that researches a company and drafts AI/GenAI opportunities plus a sales pitch |

## Requirements

- Python **3.14+** (see `.python-version`)
- [`uv`](https://docs.astral.sh/uv/) as the package manager (`uv.lock` is committed)
- An OpenAI API key with access to a model that supports the web search tool

## Setup

1. Install dependencies:

   ```bash
   uv sync
   ```

2. Create a `.env` file in the project root with the following contents:

   ```dotenv
   OPENAI_API_KEY=sk-your-key-here
   MODEL_NAME=openai:gpt-5-nano   # optional; this is the default
   ```

   - `OPENAI_API_KEY` is required and is picked up automatically by `langchain-openai`.
   - `MODEL_NAME` is optional and accepts any LangChain model string in `provider:model` form.

## Usage

All scripts can be run with `uv run <script>` (or `python <script>` inside an activated
virtual environment).

### 1. Smoke test — `main.py`

```bash
uv run main.py
```

Builds a research deep agent with web search and invokes it once with `"Hi"`, printing the
raw result. Useful for verifying that your API key and model configuration work.

### 2. Research agent — `main2.py`

```bash
uv run main2.py
```

Prompts for a research topic, then:

- streams the agent's answer live to the terminal,
- logs each completed agent step,
- prints an execution-statistics table (input / output / reasoning tokens and the number
  of web-search actions),
- writes two files to `outputs/`:
  - `report_<YYYYMMDD_HHMMSS>.md` — the final Markdown report
    (Executive Summary, Key Findings, Detailed Analysis, Conclusion, Sources),
  - `result_<YYYYMMDD_HHMMSS>.json` — full message history, statistics, and metadata,
    with encrypted reasoning payloads stripped out.

### 3. Sales intelligence — `main-salesdig.py`

```bash
uv run main-salesdig.py
```

Prompts for a company name and (optionally) its website, then researches it and produces a
B2B sales-intelligence report covering:

1. Company overview, industry, and headquarters
2. Products, services, and target customers
3. Existing technology, cloud, and AI initiatives
4. Potential business challenges
5. Three to five AI/GenAI opportunities
6. Recommended solutions and business benefits
7. A suggested sales pitch

Output is written to `reports/` as `<company-slug>_<YYYYMMDD_HHMMSS>.md` and `.json`.
The JSON export additionally includes the collected source URLs (from inline citations)
and the raw web-search actions.

## How it works

- Each script builds an agent with `create_deep_agent(model=..., tools=[...], system_prompt=...)`.
- Web search is OpenAI's provider-hosted tool, passed as `{"type": "web_search"}`.
- `main2.py` and `main-salesdig.py` stream execution via
  `agent.stream(..., stream_mode=[...], version="v2", config={"recursion_limit": 30})`,
  consuming `"messages"` events for live text and `"values"` events for the final state
  (`main2.py` also consumes `"updates"` to log completed steps).
- Token usage is aggregated from `message.usage_metadata` on AI messages; source URLs are
  collected from `url_citation` annotations on text blocks (`main-salesdig.py` only).

## Troubleshooting

- **Authentication errors** — confirm `.env` exists in the project root and contains a
  valid `OPENAI_API_KEY`.
- **Web search not used / model errors** — the configured `MODEL_NAME` must support
  OpenAI's built-in web search tool.
- **`Recursion limit reached`** — the agents run with `recursion_limit: 30`; narrow your
  query or raise the limit in the `agent.stream(...)` call.
